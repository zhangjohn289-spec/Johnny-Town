# Phase 05B 架构记录

## 复用边界

继续使用 Phase 05A 的 WorldScene + 区域数据 + 渲染器方案。未改写物理移动、摄像机、每日运势、媒体生命周期或转场机制。woods-data.js 是不依赖 Phaser 的独立地图数据；woods-renderer.js 使用其路径、空地、树和碰撞定义绘制。regions.js 只登记区域并补一对出口。

故事对象通过 kind=story / storyId 区分，统一的 interact 流程在锁输入后 discover，再由原 ui.js 渲染。同一机制可用于以后新增的叙事对象，不复制玩家控制。

## 地图与视觉

世界 1024×768，沿用16px基础网格；路径是多段连续折线的距离场，绘制成8px阶梯像素边缘和斑驳地面，避免草甸十字形结构。主路联通入口、初始之地、岔路、古树和未来路标；工坊支路和西侧休憩支路都连接主路。

树位置由固定规则生成，避开路径和空地；同时考虑树干和树冠中心，减少遮挡重要路径。100 棵树含复用贴图与原创针叶树。树冠可遮挡树后玩家，脚部按 y 排序；实体边界为树干，路径不使用隐藏挡墙。三块岩石和五个叙事地标有显式矩形，合计108静态体。

地面与五个地标生成六张带固定 key 的纹理，首次进入森林才生成；随后跨区复用，避免反复分配。其余场景 Graphics / image 属于场景生命周期。没有新生产依赖或外部素材请求。画面仍960×640、FIT、pixelArt及摄像机整数舍入，滚动范围0..64 / 0..128。

## 两层内容

story-content.js 的 profile 是公开介绍配置，stories 是短摘要、两段扩展和象征关联说明。未经确认的具体经历标注待补充。profile始终可从I键或按钮打开，没有自动弹出或解锁前提。

story-ui.js 是现有 dialog 的内容渲染器，不创建第二个模态系统。故事扩展和日志重读使用原生 details/summary，因此支持键盘与屏幕阅读语义。快速导览的探索按钮仅关闭导览并恢复自由移动；路线指引直接可读，不传送、不强制开始任务。

M 路书新增故事区：未发现时显示编号占位，不泄露标题/正文；已发现时显示可展开全文与发现数量。区域列表继续显示尚未开放的三个未来区域。

## 存档与兼容

保持 johnny-town.world.v1 键名，记录内 version 升为2。version=1的有效存档保留原字段并追加 stories=[]。version=2只接受已登记故事ID，去重，忽略未知/畸形元素；数组缺失或损坏只清空故事部分，不丢弃有效世界位置。必需世界字段损坏或未知版本安全回到小镇。

discover只在首次E互动时写入；重复互动和日志重读不增加记录。保存先于展示故事，Esc或刷新不会丢失已发现状态。存储不可用保留内存状态并显示警告。fortune存储由原模块管理，世界迁移不会接触它。

## 生命周期

额外I键和快速导览按钮与E/M一起在create绑定、shutdown解绑。关闭面板使用原锁输入流程：速度归零、清空按键、恢复keyboard.enabled。转场仍要求显式E，安全出生点远离出口范围；森林入口(160,620)，小镇返回点(500,185)。所有场景拥有的碰撞体、显示对象、补间和环境监听按原机制清理。

## 验证策略

纯数据测试检查路径每2px的完整16px玩家AABB、8px网格连通性、全部故事/出口/出生点。浏览器用实际WASD沿路径走访五处故事及休憩支路，按非固定顺序记录；单独用body.reset设置碰撞/边界测试起点和压力测试入口，不将这些定位当作路径可达性的证据。

Edge和Chrome分别执行20次缓存切换，对同一区域的事件、刚体、collider、显示对象和纹理计数逐次比较；使用主动GC后的JS堆作为短时诊断。测试不能替代长期泄漏、GPU内存或低端设备验收。
